수업과 평가를 따로 두지 않기

수업에서 연습한 방식이 그대로 다음 활동과 평가로 이어지도록 설계하였다. 개념을 설명한 뒤 별도의 시험 과제를 갑자기 제시하기보다, 수업 중 짧은 실습에서 사용한 사고 과정과 도구를 점차 확장해 하나의 문제 해결 활동으로 연결하였다.

개념 이해
→ 짧은 실습
→ 예제 분석·수정
→ 스스로 문제 해결
→ 수업 시간 안에서 결과물 완성
→ 실행·테스트·수정
→ 배움 기록과 성찰

Google Classroom을 수업 작업 공간으로 활용

Google Classroom은 공지와 과제 제출만을 위한 공간이 아니라 수업의 흐름을 이어 주는 작업 공간으로 활용하였다. 실습 자료, Colab 파일, 데이터, 참고 링크, 샘플 자료를 한곳에서 제공하고 학생은 같은 공간에서 결과물을 제출하도록 하였다.

활용수업 설계에서의 역할
수업 자료 배포실습 코드·데이터·참고 자료를 수업 직전에 같은 위치에서 제공하여 시작 시간을 줄임
실습 제출짧은 연습부터 프로젝트 결과물까지 같은 흐름 안에서 누적하여 학생의 학습 과정을 확인
수정과 재제출한 번의 제출로 끝내기보다 실행 결과와 피드백을 바탕으로 수정할 수 있도록 운영
수업 기록어떤 자료를 언제 사용했고 어떤 활동으로 이어졌는지 수업의 시간 순서를 남김

수업 시간 안에서 수행하는 과정 중심 평가

평가는 결과물만 받아 채점하는 방식보다, 학생이 수업 시간 안에서 문제를 이해하고 해결 방법을 정하고 구현·수정하는 과정을 함께 볼 수 있도록 구성하였다. 교사가 같은 공간에서 과정을 관찰할 수 있기 때문에 학생이 실제로 어떤 판단을 했는지, 어디에서 막혔는지, 피드백 이후 무엇을 바꾸었는지를 확인하기 쉽다.

과정교사가 확인하는 것
문제 이해문제의 핵심을 파악하고 필요한 정보를 구분하는가
계획해결 순서와 사용할 데이터·도구·프로그래밍 요소를 스스로 정하는가
구현배운 개념을 실제 코드나 결과물에 적용하는가
테스트와 수정오류나 예상과 다른 결과를 확인하고 원인을 찾아 개선하는가
설명과 성찰완성된 결과뿐 아니라 선택 이유, 한계, 개선 방향을 자신의 말로 설명하는가

실습에서 프로젝트로 확장하기

처음부터 큰 프로젝트를 요구하지 않고 작은 실습에서 필요한 도구를 먼저 익힌 뒤, 학생이 스스로 선택하고 판단해야 하는 범위를 넓혀 갔다. Python에서는 입출력·변수·조건·반복과 같은 기본 요소를 짧게 연습한 뒤 실제 문제 해결로 연결했고, 데이터 수업에서는 시각화 예제를 경험한 뒤 공개 데이터를 탐색하고 필요한 속성을 선택해 해석하도록 확장하였다.

완성 코드를 제공할 때의 기준

정보 수업에서 모든 코드를 처음부터 작성하는 것만을 목표로 두지 않았다. 학습 목표가 알고리즘의 비교, 데이터 해석, 장치의 동작, 디버깅처럼 코드 작성 자체와 다른 곳에 있을 때는 비교적 큰 예제 코드를 제공하고 학생이 읽고 수정하고 실행하도록 하였다.

정렬 알고리즘처럼 구조가 긴 코드는 완성된 함수의 흐름을 따라가며 결과를 비교하게 했고, 피지컬 컴퓨팅에서는 인공지능이 생성한 코드도 디버깅 대상으로 활용하였다. 중요한 것은 코드를 누가 처음 작성했는가보다, 학생이 코드의 역할을 이해하고 문제 상황에 맞게 판단·수정할 수 있는가에 두었다.

프로젝트 주제의 연속성

학생이 매 활동마다 전혀 새로운 주제를 만드는 대신 이전 활동에서 관심을 가진 주제를 다음 프로젝트에서도 참고할 수 있도록 안내하였다. 데이터 분석에서 다룬 관심 분야를 이후 문제 해결이나 다른 프로젝트로 이어 가면 한 학생의 탐구가 단절된 과제 모음이 아니라 하나의 학습 맥락으로 남을 수 있다.

인공지능을 다루는 방식

1학년 정보에서는 교과서의 인공지능 단원을 별도의 깊은 이론 수업으로 확장하기보다, 2학년 「인공지능 기초」에서 체계적으로 학습하도록 계열성을 두었다. 대신 1학년에서는 코드 생성 결과를 검토하고 디버깅하거나 문제 해결 과정에서 인공지능 도구를 활용하는 등 실제 활용 경험을 다른 단원 속에 포함하였다.

수업 후에는 배움 기록 남기기

프로젝트나 실습이 끝난 뒤에는 무엇을 만들었는지만 남기지 않고, 어떤 개념을 사용했는지, 무엇이 어려웠는지, 어떻게 해결했는지, 다음에는 무엇을 바꿀 것인지 정리하도록 하였다. 이 기록은 교사가 수업 이해도를 확인하는 자료이면서 학생이 자신의 학습 과정을 다시 보는 자료가 된다.

처음 수업을 설계할 때

설계 질문확인할 점
학생이 이미 아는 것은?새 개념을 모두 설명하기보다 이전 학습에서 가져올 수 있는 부분을 먼저 확인
이번 시간에 직접 해야 하는 것은?개념 이해·코드 작성·분석·디버깅 중 실제 학습 목표를 한정
어디까지 제공할 것인가?데이터·예제 코드·템플릿을 제공할 범위와 학생이 스스로 결정할 범위를 구분
과정을 어떻게 남길 것인가?Classroom 제출, 코드, 문서, 배움 기록 등 수업 중 자연스럽게 남는 자료 활용
다음 활동과 어떻게 연결할 것인가?이번 실습이 다음 프로젝트의 어떤 판단이나 기술로 이어지는지 미리 설계

수업의 목표는 정해진 정답을 빠르게 제출하는 데 두기보다, 학생이 문제를 이해하고 자신의 해결 과정을 만들어 가며 실행 결과를 근거로 다시 수정하는 경험을 갖게 하는 데 두었다.
