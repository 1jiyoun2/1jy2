수업과 평가를 한 흐름으로 설계

수업에서 연습한 방식이 다음 활동과 평가로 자연스럽게 이어지도록 구성했다. 개념 설명 뒤에 별도의 과제를 갑자기 제시하기보다, 짧은 실습에서 사용한 사고 과정과 도구를 조금씩 확장하여 하나의 문제 해결 활동으로 연결했다.

개념 이해
→ 짧은 실습
→ 예제 분석·수정
→ 스스로 문제 해결
→ 수업 시간 안에서 수행
→ 실행·테스트·수정
→ 배움 기록과 성찰

Google Classroom과 Colab을 중심으로 운영

Google Classroom은 공지와 과제 제출 공간을 넘어 수업 자료와 실습 흐름을 모아 두는 중심 공간으로 활용했다. Colab 링크, 데이터 파일, 참고 자료, 샘플 문서 등을 Classroom에서 바로 연결하고 학생도 같은 공간에서 결과물을 제출하도록 했다.

Colab과의 연결이 편리해 별도의 개발 환경 설치 없이 바로 실습을 시작할 수 있었고, 코드와 실행 결과가 한 문서에 남아 수업 중 확인하기 좋았다. 수정 이력과 제출 기록이 그대로 남는 점도 유용했다. 학생이 언제 어떤 부분을 바꾸었는지, 한 번에 완성한 것인지 여러 번 수정한 것인지, 수업 중 어디에서 막혔는지 등을 나중에 다시 확인할 수 있어 과정 중심 평가와 수업 기록에 잘 맞았다.

활용운영 방식
자료 배포실습 코드·데이터·참고 링크를 Classroom에서 바로 제공
Colab 실습설치 없이 실행하고 코드와 결과를 같은 문서 안에서 확인
제출 기록실습과 프로젝트 결과물을 같은 공간에 누적
수정 이력학생의 수정 과정과 시간 흐름을 확인하여 수업 중 상황을 파악
수업 기록자료 게시 시점과 활동 순서가 남아 학기 전체 흐름을 다시 복기하기 쉬움

수업 시간 안에서 과정 중심 평가

수행평가는 가능한 한 수업 시간 안에서 진행했다. 결과물만 보는 것보다 학생이 문제를 이해하고 해결 방법을 정하고 구현·수정하는 과정을 함께 보는 것이 중요하다고 생각했다. 같은 시간과 공간에서 진행하면 실제로 어떤 판단을 했는지, 어디에서 막혔는지, 피드백 이후 무엇을 바꾸었는지를 확인하기 쉬웠다.

완성 속도보다 해결 과정의 변화에 더 주목했다. 처음 선택한 방법이 잘 되지 않았을 때 다른 방법을 시도하는지, 실행 결과를 근거로 코드를 수정하는지, 자신의 선택 이유를 설명할 수 있는지를 수업 과정에서 확인했다.

과정수업에서 본 부분
문제 이해문제의 핵심을 파악하고 필요한 정보를 구분하는 과정
계획해결 순서와 사용할 데이터·도구·프로그래밍 요소를 정하는 과정
구현배운 개념을 실제 코드나 결과물에 적용하는 과정
테스트와 수정예상과 다른 결과를 확인하고 원인을 찾아 다시 고치는 과정
설명과 성찰선택 이유, 한계, 개선 방향을 자신의 말로 정리하는 과정

실습에서 프로젝트로 확장

처음부터 큰 프로젝트를 요구하지 않고 작은 실습에서 필요한 도구를 먼저 익힌 뒤 학생이 스스로 선택하고 판단해야 하는 범위를 넓혀 갔다. Python에서는 입출력·변수·조건·반복과 같은 기본 요소를 짧게 연습한 뒤 실제 문제 해결로 연결했고, 데이터 수업에서는 간단한 시각화 경험에서 출발해 공개 데이터를 탐색하고 필요한 속성을 선택해 해석하는 활동으로 확장했다.

모든 코드를 처음부터 쓰게 하지는 않음

정보 수업의 목표가 항상 코드를 처음부터 작성하는 데 있다고 보지는 않았다. 알고리즘 비교, 데이터 해석, 장치 동작, 디버깅처럼 학습 목표가 다른 곳에 있을 때는 비교적 큰 예제 코드를 제공하고 학생이 읽고 수정하고 실행하도록 했다.

정렬 알고리즘처럼 구조가 긴 코드는 완성된 함수의 흐름을 따라가며 결과를 비교했고, 피지컬 컴퓨팅에서는 인공지능이 생성한 코드도 디버깅 대상으로 활용했다. 코드의 출처보다 학생이 역할을 이해하고 문제 상황에 맞게 판단·수정할 수 있는지를 중요하게 보았다.

질문으로 선택 이유를 드러내기

실습 중에는 정답을 바로 알려주기보다 “왜 이 값을 골랐는지”, “이 결과가 예상과 다른 이유가 무엇인지”, “다른 방법으로 하면 무엇이 달라지는지”를 묻는 방식으로 학생의 생각을 확인했다. 같은 코드를 실행해도 선택 이유와 결과 해석은 학생마다 달라질 수 있어, 질문을 통해 그 차이를 드러내는 편이 과정 확인에 도움이 되었다.

주제의 연속성

매 활동마다 완전히 새로운 주제를 고르게 하기보다 이전 활동에서 관심을 가졌던 주제를 다음 프로젝트에서도 이어갈 수 있도록 했다. 데이터 분석에서 다룬 관심 분야를 이후 문제 해결 활동이나 다른 프로젝트와 연결하면 한 학생의 학습이 단절된 과제 모음이 아니라 하나의 탐구 흐름으로 남았다.

인공지능은 다른 단원 안에서도 활용

1학년 정보에서는 인공지능 이론을 별도로 깊게 확장하기보다 2학년 「인공지능 기초」에서 체계적으로 학습하도록 계열성을 두었다. 대신 1학년에서는 코드 생성 결과를 검토하고 디버깅하거나 문제 해결 과정에서 인공지능 도구를 활용하는 등 실제 활용 경험을 다른 단원 속에 포함했다.

배움 기록

프로젝트나 실습이 끝난 뒤에는 무엇을 만들었는지만 남기지 않고, 어떤 개념을 사용했는지, 무엇이 어려웠는지, 어떻게 해결했는지, 다음에는 무엇을 바꿀 것인지 정리하도록 했다. 학생의 결과물과 함께 이런 기록을 보면 수업 중에는 놓쳤던 변화도 나중에 다시 확인할 수 있었다.

정해진 답을 빠르게 완성하는 것보다, 문제를 이해하고 해결 방법을 선택한 뒤 실행 결과를 근거로 다시 수정하는 경험을 수업 안에서 충분히 하게 하는 것을 중요하게 두었다.
